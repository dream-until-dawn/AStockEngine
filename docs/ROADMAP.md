# AStockEngine 版本路线图

> 本文档是项目的**活文档**，版本内容或优先级发生调整时同步更新。
> 最后更新：2026-08-28

## 项目定位

面向中国 A 股的策略回测系统。数据层用 Python，回测引擎用 Go。

引擎目标是**通用、模块化、可单步**，最终支撑三类使用场景：

1. **交互式单步调试** —— Web 端配置参数，逐步推进，查看每一步的信号、订单、成交与账户变化
2. **批量策略海选** —— 批量传入配置列表并发回测，输出稳健参数区域
3. **实盘预测** —— 用同一套引擎与策略代码，产出「今日动作」

---

## 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 数据获取 | Python + AkShare | ETL 层做成**数据源适配器接口**，AkShare 为第一实现，后续可换 Tushare / BaoStock 而不动下游 |
| 数据存储 | Parquet（列式文件） | Python 与 Go 的唯一耦合点是 **schema**，不做 cgo / gRPC 互调，边界越薄越好 |
| 回测引擎 | Go 1.26+ | 事件驱动模型下 Go 的性能与类型安全是关键收益 |
| 策略形态 | **Go 原生编译** | 策略实现 `Strategy` interface 编译进引擎；Web 端配参数不写逻辑 |
| 数据频率 | **日线 + 分钟线** | 时间模型从 v0.1 起就是多频率的；分钟线实现延后至 v0.5 |
| 结果库 | DuckDB | 海选结果存储与查询 |

## 核心设计约束

以下几条是**架构级不可妥协项**，任何版本的实现都不得违反。

### C1. 未来函数防护

策略**绝不能拿到全量数据切片**，必须通过带时间游标的 `DataGateway` 访问，只能读到 `<= 当前决策时点` 的数据。用 Go 的类型系统在**编译期**禁止越界访问，而不是靠自觉。

### C2. 复权处理

**存原始价 + 复权因子**，引擎内部按需动态复权。

前复权价格会随每次新的除权事件变化 —— 昨天算出的信号今天就变了，既导致回测不可复现，本身也是一种未来函数。分红送股必须真实反映到账户（现金分红入账、送股增加持仓），而不是只调整价格。

### C3. 幸存者偏差

股票池**必须包含已退市股票**，否则回测收益系统性虚高。指数成分股必须是 point-in-time 的（回测 2019 年时用的是当时的沪深 300 成分，而非今天的）。

### C4. 引擎核心是状态机

核心必须是 `Step() (Event, error)` 的状态机，**不能是内部的 for 循环**。单步调试、批量海选、实盘增量三种模式共用同一个核心，只换 Driver 与 Recorder。

写成 for 循环后再改状态机等于重写，此约束在 v0.2 落地时必须严格遵守。

### C5. 可复现性

`配置哈希 + 数据版本 + 引擎版本 → 结果指纹`。同配置两次运行必须**逐笔一致**。海选出的策略必须能一键重跑复现，否则海选没有意义。

### C6. 回测—实盘一致性

「今日动作」本质上是**回测跑到今天再多跑一步**。同一份策略代码、同一个引擎核心，只替换 `DataFeed`（历史→实时）与 `Executor`（模拟成交→信号输出）。

这要求引擎状态**可序列化 / 快照恢复**，否则每天实盘都要从头重算多年数据。

### C7. 过拟合防护

跑 1000 组参数，排名第一的那组大概率是运气（多重检验问题）。

**海选的输出不是「排名第一的参数」，而是「稳健的参数区域」。** 必须支持样本内/样本外切分（IS/OOS）、Walk-Forward 滚动验证、参数高原邻域稳健性评分。

### C8. A 股交易规则

以下规则内建于 `Market` / `Broker` / `Fee` 模块：

- **T+1**：当日买入不可卖出
- **涨跌停**：主板 10%、ST 5%、创业板/科创板 20%、北交所 30%
- **一字板无法成交**：需在撮合器中建模，不能假设总能成交
- **停牌**：跳过，不产生成交
- **整手**：买入 100 股整数倍，卖出可零股
- **竞价**：集合竞价与连续竞价区分
- **费用**：佣金万 2.5（最低 5 元）、印花税卖出 0.05%、过户费双向 0.001%
- **成交量约束**：单笔成交不超过当日成交量的 X%，避免对流动性差的标的产生不真实的大额成交

## 架构分层

```
┌─────────────────────────────────────────────────┐
│  Python ETL   AkShare/... → Parquet             │  ← 唯一耦合点：schema
└─────────────────────────────────────────────────┘
                      ↓  (文件)
┌─────────────────────────────────────────────────┐
│  DataGateway   时间游标 · 复权 · 未来函数防护     │
├─────────────────────────────────────────────────┤
│  Core Engine   Step() 状态机 · 事件总线           │
│  ┌──────────┬──────────┬──────────┬───────────┐ │
│  │ Market   │ Broker   │ Portfolio│ Recorder  │ │
│  │ 日历/规则 │ 撮合/滑点 │ 账本      │ 三档记录   │ │
│  ├──────────┼──────────┼──────────┼───────────┤ │
│  │ Fee      │ Sizer    │ Risk     │ Metrics   │ │
│  └──────────┴──────────┴──────────┴───────────┘ │
│         全部 interface + registry 装配            │
├─────────────────────────────────────────────────┤
│  Driver   StepDriver（交互） │ BatchDriver（海选） │
├─────────────────────────────────────────────────┤
│  API      HTTP / WebSocket                       │
└─────────────────────────────────────────────────┘
```

### 模块职责边界

| 模块 | 性质 | 职责 |
|---|---|---|
| `Market` | 配置 | 交易日历、交易规则、涨跌停计算、停复牌 |
| `Broker` | 行为 | 订单 → 成交，处理涨跌停/停牌/成交量约束/滑点 |
| `Portfolio` | **状态（账本）** | 现金、持仓、可用/冻结、权益、盈亏、除权除息入账 |
| `Sizer` | **决策（策略侧）** | 给定信号计算下单数量 |
| `Risk` | 行为 | 下单前拦截：单票上限、集中度、回撤熔断 |
| `Fee` | 配置 | 佣金、印花税、过户费 |
| `Recorder` | 观测 | 三档级别记录（None / Summary / Full） |
| `Metrics` | 观测 | 绩效指标计算 |

> `Portfolio`（账本，是状态）与 `Sizer`（仓位决策，是策略侧）必须分离。
> 混在一起是回测框架最常见的架构债。

### 关于「热插拔」

Go 的 `plugin` 包**在 Windows 上完全不支持**，且要求主程序与插件用完全相同的 Go 版本和依赖版本编译，实践中极其脆弱。

本项目采用 **接口 + registry + 配置装配**：各模块定义 interface，实现在 `init()` 中注册到全局 registry，运行时按配置中的字符串选择实现。

```json
{ "fee": "a_share_2023", "slippage": "fixed_bps", "sizer": "equal_weight" }
```

效果上达成「任意组合」，代价仅是新增实现需重新编译（编译耗时约 2 秒，可接受）。

若后续确实需要不重编译即可改策略逻辑，那是**脚本层**（表达式引擎 / Starlark / WASM）的事，不是 plugin 的事，视需要在 v1.0 之后评估。

### 关于多市场泛用性

**接口按多市场设计，实现只做 A 股。** 做两套实现来验证抽象是浪费，但接口中不得出现写死的 `涨跌停 10%` 这类常量。

## 版本排期

标记：⭐ 关键路径（做错要返工） · 🔗 依赖前置版本

### v0.0 — 技术验证（探针）

**目标**：确认 AkShare 能否支撑数据层的设计假设。

整个数据层的设计假设都建立在这三项能力上，赌错了 v0.1 要重做。

| 待验证项 | 影响 | 不满足时的退路 |
|---|---|---|
| 退市股历史行情能否获取 | 拿不到即触发 C3 幸存者偏差，回测结论不可信 | 换 Tushare Pro（需积分）或 BaoStock 补数 |
| 复权因子能否单独获取 | 仅有 qfq/hfq 价格而无因子时需反推，存在精度问题 | 用 hfq + 原始价反推因子，验证精度 |
| 历史分钟线深度 | 部分接口仅提供近 5 天 / 近 1 月 | 改为每日增量落盘、长期积累，历史段接受缺失 |

**交付**：探针脚本 + 实测结论文档，决定是否需要备用数据源。 **量级 S**

---

### v0.1 ⭐ — 数据地基

**目标**：拿到干净、可复现、含退市股的本地数据集。

- 数据源适配器接口（AkShare 为第一实现）
- Schema 定义（6 张表）：
  - `instruments` — 股票基本信息：代码、名称、上市日、退市日、板块、ST 时间段
  - `calendar` — 交易日历
  - `bar_daily` — 日线：OHLCV、成交额、换手率、涨跌停价、停牌标记
  - `bar_minute` — 分钟线（v0.1 仅定义 schema 与分区，实现见 v0.5）
  - `adj_factor` — 复权因子（独立表，见 C2）
  - `corporate_action` — 分红送配
- 分区布局：日线按 `year=`；分钟线按 `symbol_prefix= / year= / month=`
- 增量更新 + 断点续传 + 频率限制退避
- 数据质量校验器：缺失交易日、价格跳变、复权因子突变、量价矛盾

**验收**：一条命令拉取全量 A 股日线落 Parquet，并产出质量报告。 **量级 L**

---

### v0.2 ⭐ — 引擎核心闭环

**目标**：单步状态机 + A 股规则，跑通最简策略。

- `Bar` / `Freq` 多频率时间模型（接口多频率，实现仅日线路径）
- `DataGateway`：时间游标，编译期防未来函数（C1）
- Core：`Step() (Event, error)` 状态机（C4）
- `Market`：交易日历、涨跌停计算、停牌、T+1
- `Broker`：限价/市价单、一字板拒绝成交、成交量约束、滑点
- `Portfolio`：现金/持仓/冻结/权益/盈亏，除权除息入账
- `Fee`：佣金 + 印花税 + 过户费（A 股 2023 版）
- `Strategy` interface + BuyAndHold + 双均线两个样例策略
- CLI 跑通，输出净值序列

**验收**：手工核算一笔完整交易的费用与持仓，与引擎输出**逐分位一致**。 **量级 L**

---

### v0.3 — 模块化装配

**目标**：配置驱动装配 + Web 表单的元数据基础。

- registry + `init()` 注册，JSON 配置装配
- **ParamSpec 参数自描述**：策略注册时声明参数名称/类型/范围/步长/默认值

  ```go
  func (s *MACross) Params() []ParamSpec {
      return []ParamSpec{
          {Name: "fast", Type: Int, Default: 5,  Min: 2, Max: 60,  Step: 1},
          {Name: "slow", Type: Int, Default: 20, Min: 5, Max: 250, Step: 1},
      }
  }
  ```

  该机制同时支撑三处：Web 自动生成表单（v0.4/v1.0）、海选自动展开参数网格（v0.6）、配置校验。
- `Sizer` / `Risk` / `Slippage` / `Fee` 全部可替换
- `Recorder` 三档级别（None / Summary / Full）
- 完整指标集：年化收益、夏普、索提诺、最大回撤、卡玛、胜率、盈亏比、换手率、基准超额
- 结果指纹（C5）

**验收**：换 JSON 配置即可改变引擎行为；同配置两次运行结果逐笔一致。 **量级 M**

---

### v0.4 🔗v0.3 — 单步 API 与状态快照

**目标**：需求 3 —— 单步运行与细节记录。

- HTTP + WebSocket 服务
- 会话管理：create / step / run-to / pause / reset / inspect
- **状态快照：序列化与恢复**
- 结构化事件流：每步的信号 → 订单 → 成交 → **拒单原因** → 持仓变化 → 账户快照
- 拒单原因必须结构化（涨跌停 / 停牌 / 资金不足 / T+1 / 风控拦截），这是单步调试的核心价值

> 状态快照放在 v0.4 而非 v0.7：它同时是单步 API 的 reset/回放能力与 v0.7 实盘增量模式的共同基础，一次做对比事后返工便宜得多。

**验收**：wscat 能完整驱动一次回测，每步细节可见。 **量级 M**

---

### v0.5 🔗v0.1 — 分钟线落地

**目标**：多频率真正落地。

- 分钟线 ETL（应对 AkShare 历史深度限制：增量积累）
- 分片加载 + LRU 缓存
- 混合频率：日线选股 + 分钟线执行

> 数据量级参考：全 A 股分钟线约 3 亿行/年，10 年 Parquet 压缩后约 200–400 GB。日线可全量进内存，分钟线不行。

**验收**：分钟级回测跑通且内存占用可控。 **量级 L**

---

### v0.6 🔗v0.3 — 策略海选

**目标**：需求 4 —— 批量配置列表海选。

- `BatchDriver`：worker pool，按 CPU 核数并发
- 从 ParamSpec 自动展开参数网格
- 结果库（DuckDB）+ 查询
- **IS/OOS 切分 + Walk-Forward 滚动验证**（C7）
- **参数高原稳健性评分**：看邻域参数是否同样表现良好，而非单点尖峰

**验收**：1000 组参数跑完，输出**稳健参数区域**而非 top-1 排名。 **量级 L**

---

### v0.7 🔗v0.4 — 实盘预测

**目标**：需求 5 —— 成功策略下的实盘预测与今日动作。

- 增量模式：加载快照 + 喂入当日数据 + 多跑一步
- `Executor` 抽象：模拟成交 / 信号输出
- 今日动作产出：买/卖/持有 + 目标仓位 + 委托价格区间
- 实盘偏差监控：实际成交 vs 回测假设

**验收**：同策略同数据下，回测最后一天的动作 **==** 实盘模式产出的动作（C6）。 **量级 M**

---

### v1.0 — Web 前端

- ParamSpec 驱动的参数表单
- 单步调试界面：K 线 + 持仓 + 事件流
- 海选结果可视化：参数热力图、稳健区域
- 今日动作看板

**量级 L**

## 排期判断

**v0.1 + v0.2 值得慢。** 这两个版本约占整体工作量的 40%，但决定 100% 的正确性。时间游标、复权模型、`Step()` 状态机这三件事写错了，后续每个版本都要返工。

## 分支与提交约定

```
develop ──●──●──●────────●────  日常开发
           \        /      \
            feature/xxx     └─ merge --no-ff → main + tag v0.1.0
```

- `main` —— 主分支，只接受从 `develop` 的 `--no-ff` 合并，每次合并打 tag
- `develop` —— 日常开发分支
- `feature/*` —— 较大的模块从 `develop` 拉出，完成后并回 `develop`
