# AStockEngine 版本路线图

> 本文档是项目的**活文档**，版本内容或优先级发生调整时同步更新。
> 最后更新：2026-08-28（v0.0 探针完成，数据源方案据实测结果修订）

## 项目定位

面向中国 A 股的策略回测系统。数据层用 Python，回测引擎用 Go。

引擎目标是**通用、模块化、可单步**，最终支撑三类使用场景：

1. **交互式单步调试** —— Web 端配置参数，逐步推进，查看每一步的信号、订单、成交与账户变化
2. **批量策略海选** —— 批量传入配置列表并发回测，输出稳健参数区域
3. **实盘预测** —— 用同一套引擎与策略代码，产出「今日动作」

### 当前范围

| 维度 | 当前范围 | 远期 |
|---|---|---|
| 市场 | 仅 A 股 | 美股、日经、加密货币 |
| 频率 | **仅日线**（Web 端向用户明示） | 分钟线（随远期市场一并引入） |
| 标的 | 个股 + **ETF** | —— |
| 因子 | **纯技术面**（量价） | —— |

「纯技术面」是明确的范围约束：不采集、不存储、不计算市盈率、市净率、
财报等基本面数据。这会显著简化 schema 与 ETL，也意味着策略层不应出现基本面信号。

## 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 数据获取 | Python + **BaoStock（个股）/ 新浪（ETF、复权因子）** | 见下方数据源分工；东财因限流弃用 |
| 数据存储 | Parquet（列式文件） | Python 与 Go 的唯一耦合点是 **schema**，不做 cgo / gRPC 互调，边界越薄越好 |
| 回测引擎 | Go 1.26+ | 事件驱动模型下 Go 的性能与类型安全是关键收益 |
| 策略形态 | **Go 原生编译** | 策略实现 `Strategy` interface 编译进引擎；Web 端配参数不写逻辑 |
| 数据频率 | **仅日线** | 时间模型仍按多频率设计（见 C9），但当前只实现日线 |
| 结果库 | DuckDB | 海选结果存储与查询 |

### 数据源分工（依据 v0.0 实测，详见 `docs/probe/REPORT-v0.0.md`）

| 数据 | 来源 | 理由 |
|---|---|---|
| 个股日线（含退市股） | **BaoStock** | 唯一同时提供 `preclose` / `tradestatus` / `isST` 的源；无限流 |
| point-in-time 股票池 | **BaoStock** `query_all_stock(day=)` | 直接支撑约束 C3 |
| 个股复权因子 | **新浪** `adjust="hfq-factor"` | 16 位精度事件式因子，实测还原误差 < 1e-6 |
| ETF 日线 | **新浪** `fund_etf_hist_sina` | BaoStock 无 ETF 行情；新浪覆盖全历史 |
| ETF 复权 | 🟡 **未解决**，v0.1 期间收口 | 见报告 3.1 |
| 交易日历 | BaoStock / 新浪均可 | —— |
| 分红送配 | BaoStock | 字段最全（登记日/除权日/派息日/送股/转增） |

> **东财弃用**：`push2his.eastmoney.com` 约 10 次请求即触发 IP + 端点级封禁，
> 实测 **≥45 分钟未恢复**（探针跑满上限，真实时长未测出），无法支撑批量 ETL。
> 按此速率回补 1647 只 ETF 需 120 小时以上，故也不再作为 ETF 复权的首选退路。

## 核心设计约束

以下几条是**架构级不可妥协项**，任何版本的实现都不得违反。

### C1. 未来函数防护

策略**绝不能拿到全量数据切片**，必须通过带时间游标的 `DataGateway` 访问，只能读到 `<= 当前决策时点` 的数据。用 Go 的类型系统在**编译期**禁止越界访问，而不是靠自觉。

### C2. 复权处理

**存原始价 + 复权因子**，引擎内部按需动态复权。

前复权价格会随每次新的除权事件变化 —— 昨天算出的信号今天就变了，既导致回测不可复现，本身也是一种未来函数。分红送股必须真实反映到账户（现金分红入账、送股增加持仓），而不是只调整价格。

### C3. 幸存者偏差

股票池**必须包含已退市股票**，否则回测收益系统性虚高。指数成分股必须是 point-in-time 的（回测 2019 年时用的是当时的沪深 300 成分，而非今天的）。

### C4. 引擎核心是状态机

核心必须是 `Step() (Event, error)` 的状态机，**不能是内部的 for 循环**。单步调试、批量海选、实盘增量三种模式共用同一个核心，只换 Driver 与 Recorder。

写成 for 循环后再改状态机等于重写，此约束在 v0.2 落地时必须严格遵守。

### C5. 可复现性

`配置哈希 + 数据版本 + 引擎版本 → 结果指纹`。同配置两次运行必须**逐笔一致**。海选出的策略必须能一键重跑复现，否则海选没有意义。

### C6. 回测—实盘一致性

「今日动作」本质上是**回测跑到今天再多跑一步**。同一份策略代码、同一个引擎核心，只替换 `DataFeed`（历史→实时）与 `Executor`（模拟成交→信号输出）。

这要求引擎状态**可序列化 / 快照恢复**，否则每天实盘都要从头重算多年数据。

### C7. 过拟合防护

跑 1000 组参数，排名第一的那组大概率是运气（多重检验问题）。

**海选的输出不是「排名第一的参数」，而是「稳健的参数区域」。** 必须支持样本内/样本外切分（IS/OOS）、Walk-Forward 滚动验证、参数高原邻域稳健性评分。

### C8. A 股交易规则

以下规则内建于 `Market` / `Broker` / `Fee` 模块，且**必须按标的类型分流**——
个股与 ETF 的成本模型不同，同一策略跑两者会得出不同结论。

| 规则 | 个股 | ETF |
|---|---|---|
| 印花税 | 卖出 0.05% | **免征** |
| 过户费 | 沪深双向 0.001% | **免征** |
| 佣金 | 万 2.5，最低 5 元 | 同左（费率可能更低） |
| 交收 | T+1 | 股票型 T+1；**跨境 / 黄金 / 债券 T+0** |
| 涨跌停 | 主板 10% / 创业板科创板 20% / ST 5% / 北交所 30% | 10%；跟踪创业板科创板指数的为 20% |
| 最小单位 | 买入 100 股整数倍，卖出可零股 | 100 份起，100 份为单位 |

共同规则：

- **一字板无法成交**：需在撮合器中建模，不能假设总能成交
- **停牌**：不产生成交，由 `tradestatus` 标记识别
- **成交量约束**：单笔成交不超过当日成交量的 X%，避免对流动性差的标的产生不真实的大额成交

#### C8.2 涨跌幅规则有时间维度 ⚠️

涨跌幅限制**不是常量**，随监管规则变更。已确认的生效日：

| 生效日 | 变更 |
|---|---|
| 2026-07-06 | 沪深北新版交易规则，主板风险警示股（ST/*ST）由 **5% → 10%** |
| 2020-08-24 | 创业板注册制改革，由 **10% → 20%** |

两者均由 v0.1 的板块自洽校验从数据中发现后查证确认
（详见 [ETL.md](ETL.md) 6.6）。**Market 模块必须按日期分段实现**，
写成静态常量会导致回测 2026-07-06 之前的 ST 股放行本该被拦截的成交。

参考实现：`etl/build_bars.py: limit_ratio(board, is_st, trading_day)`。

#### C8.3 明确不建模的机制

- **集合竞价**：不建模竞价阶段的订单排队、价格发现与可撤单窗口。

  这一决定与「仅日线」的范围是自洽的 —— 日线数据本就不含竞价阶段的委托明细，
  即便想建模也无数据支撑。实际影响仅限于：`ts_open` 取 09:30（连续竞价开始）
  而非 09:25；Broker 把开盘价、收盘价当作**成交价假设**使用，
  而不模拟产生这些价格的撮合过程。

  一字板仍然建模 —— 它依赖的是涨跌停价与成交量，不依赖竞价机制。

#### C8.1 涨跌停基准必须用 `preclose` ⚠️

**涨跌停价的基准是「除权调整后的前收盘价」，不是前一交易日的实际收盘价。**

v0.0 实测证据（详见 `docs/probe/REPORT-v0.0.md` 2.3）：

| 标的 | 日期 | 前一日收盘 | 按前收算的跌停 | 实际最低 |
|---|---|---|---|---|
| 002594 比亚迪 | 2025-07-29（除权日） | 337.00 | 303.30 | **109.77** |
| 300750 宁德时代 | 2023-04-26（除权日） | 385.90 | 308.72 | **210.01** |

若用 `close.shift(1)` 推导涨跌停价，Broker 会在每个大比例送转的除权日
误判「跌停不能卖 / 涨停不能买」。大比例送转每年都有，不是边缘情况。

→ `bar` 表必须存 `preclose` 字段（A 股扩展列）。

### C9. 数据源与市场的独立性

数据源适配器不是「将来可能要换」的预留，而是**核心设计**：v0.0 已经导致
主力源从 AkShare 换成 BaoStock，且 ETF 与个股走的是不同的源。

- **数据源可换**：新增或替换数据源不得改动 DataGateway 以上的任何代码
- **市场可扩**：接口按多市场设计，实现只做 A 股。接口中不得出现写死的
  `涨跌停 10%`、`T+1`、`100 股整手`、`9:30-15:00` 这类常量 —— 它们属于
  某个 `Market` 实现的配置，而非引擎的假设
- **频率可扩**：当前只实现日线，但时间模型保持多频率形态（`Bar` 带 `Freq`，
  `Step()` 步进单位是「下一个事件时点」而非「下一天」），以便远期接入
  美股 / 日经 / 加密货币的分钟线时无需重构核心

远期市场的已知差异（接口设计时需容纳，当前不实现）：
T+0 交收、做空、无涨跌停、24×7 连续交易、非整数最小交易单位、多币种。

### C10. 纯技术面

引擎只消费量价数据。不采集、不存储、不计算市盈率、市净率、财报等基本面字段。

这一约束同时作用于 schema（`bar` 表不含估值列）、ETL（不拉财务接口）
与策略层（不应出现基本面信号）。

## 架构分层

```
┌─────────────────────────────────────────────────┐
│  Python ETL   AkShare/... → Parquet             │  ← 唯一耦合点：schema
└─────────────────────────────────────────────────┘
                      ↓  (文件)
┌─────────────────────────────────────────────────┐
│  DataGateway   时间游标 · 复权 · 未来函数防护     │
├─────────────────────────────────────────────────┤
│  Core Engine   Step() 状态机 · 事件总线           │
│  ┌──────────┬──────────┬──────────┬───────────┐ │
│  │ Market   │ Broker   │ Portfolio│ Recorder  │ │
│  │ 日历/规则 │ 撮合/滑点 │ 账本      │ 三档记录   │ │
│  ├──────────┼──────────┼──────────┼───────────┤ │
│  │ Fee      │ Sizer    │ Risk     │ Metrics   │ │
│  └──────────┴──────────┴──────────┴───────────┘ │
│         全部 interface + registry 装配            │
├─────────────────────────────────────────────────┤
│  Driver   StepDriver（交互） │ BatchDriver（海选） │
├─────────────────────────────────────────────────┤
│  API      HTTP / WebSocket                       │
└─────────────────────────────────────────────────┘
```

### 模块职责边界

| 模块 | 性质 | 职责 |
|---|---|---|
| `Market` | 配置 | 交易日历、交易规则、涨跌停计算、停复牌；**按标的类型分流**（个股 / ETF） |
| `Broker` | 行为 | 订单 → 成交，处理涨跌停/停牌/成交量约束/滑点 |
| `Portfolio` | **状态（账本）** | 现金、持仓、可用/冻结、权益、盈亏、除权除息入账 |
| `Sizer` | **决策（策略侧）** | 给定信号计算下单数量 |
| `Risk` | 行为 | 下单前拦截：单票上限、集中度、回撤熔断 |
| `Fee` | 配置 | 佣金、印花税、过户费；**按标的类型分流**（ETF 免印花税与过户费） |
| `Recorder` | 观测 | 三档级别记录（None / Summary / Full） |
| `Metrics` | 观测 | 绩效指标计算 |

> `Portfolio`（账本，是状态）与 `Sizer`（仓位决策，是策略侧）必须分离。
> 混在一起是回测框架最常见的架构债。

### 关于「热插拔」

Go 的 `plugin` 包**在 Windows 上完全不支持**，且要求主程序与插件用完全相同的 Go 版本和依赖版本编译，实践中极其脆弱。

本项目采用 **接口 + registry + 配置装配**：各模块定义 interface，实现在 `init()` 中注册到全局 registry，运行时按配置中的字符串选择实现。

```json
{ "fee": "a_share_2023", "slippage": "fixed_bps", "sizer": "equal_weight" }
```

效果上达成「任意组合」，代价仅是新增实现需重新编译（编译耗时约 2 秒，可接受）。

若后续确实需要不重编译即可改策略逻辑，那是**脚本层**（表达式引擎 / Starlark / WASM）的事，不是 plugin 的事，视需要在 v1.0 之后评估。

## 数据存储设计

### 选型：本地 Parquet 文件，不引入数据库

依据 v0.0 的 P8 / P9 基准（30.7 万行真实样本，详见 `docs/probe/REPORT-v0.0.md`）。

**理由是访问模式，不是体积。** 回测不做随机点查，而是「一次加载、反复顺序扫描」：
全市场 2000 万行日线约 **350 MB**，载入内存后所有访问都是指针运算。
数据库的索引、事务、MVCC、连接池在这个场景全是纯开销。

更关键的是海选场景：**N 个 worker 共享同一份只读内存数据，零拷贝** ——
这是 Go 相对 Python 的核心优势，数据放进数据库这个优势就消失了。

同时 Parquet 是云上一等公民：对象存储直接放，DuckDB / Athena / BigQuery / Spark
都能直查，支持 range request 按行组读取，Hive 分区被普遍识别。

### 实测结论

| 变体 | 字节/行 | 全市场外推 | vs 基线 |
|---|---|---|---|
| **定点整数 + DELTA_BINARY_PACKED + zstd** | **18.30** | **349 MB** | 0.61x |
| 定点整数 + zstd(L9) | 22.64 | 432 MB | 0.76x |
| 定点整数 + zstd(L3) | 23.03 | 439 MB | 0.77x |
| float64 + zstd | 24.52 | 468 MB | 0.82x |
| float64 + snappy | 29.77 | 568 MB | 1.00x |

跨语言链路三个方向全部实测通过：Python 写 → Go 读（6/6 变体校验和一致）、
Go 写 → Python 读（含可空/布尔/字符串字段）、`CGO_ENABLED=0` 编译通过。

**保守子集原则**：只用各语言实现都成熟支持的压缩（zstd）与编码
（dictionary / plain / RLE / DELTA_BINARY_PACKED，后者已实测 Go 可读）。
不为多省几个百分点使用冷门编码 —— 那正是跨语言兼容性出问题的地方。

### 跨市场统一 schema

范围要求兼容远期的美股、期货、加密货币。P9 实测：统一 schema 仅比
A 股专用 schema 大 **2.0%**（356 MB vs 349 MB），跨市场兼容近乎免费，
因此**直接采用统一 schema，不做 A 股专用版**。

#### 层 1：bar 核心 10 列 —— 全市场严格统一

```
instrument_id  int32     引擎内部 ID，非 symbol
ts_open        int64     UTC 毫秒，bar 起始时刻（策略侧不得使用）
ts_close       int64     UTC 毫秒，bar 结束时刻（时间游标用此列）
trading_day    int32     YYYYMMDD，业务语义的交易日
open/high/low/close  int64   定点整数
volume         int64     定点整数
amount         int64     计价币种最小单位
```

引擎核心循环只读这 10 列，其名称与语义**不可变更**。
逐字段定义见 [SCHEMA.md](SCHEMA.md)。

#### 层 2：市场特定列 —— 直接附于同表

```
ashare  : + preclose, turn, tradestatus, is_st
us      : + preclose, pre_market_volume
futures : + open_interest, settlement
crypto  : + funding_rate
```

该方案的前提「Go 可用仅含核心列的 struct 读取扩展列文件」已由
`engine/cmd/subsetread` 实测验证通过，因此**无需拆分扩展表做 join**
（分表方案实测多占 1.3% 体积且读取更复杂）。

Go 侧对应两个 struct：`CoreBar`（跨市场通用）与 `AShareBar`（含扩展列）。

#### 层 3：instruments —— 统一列 + `attrs` JSON

```
instrument_id, market, symbol, name, type,
price_scale, qty_scale, quote_ccy,
list_date, delist_date, board,
attrs  string(JSON)   市场特定属性
```

`attrs` 承载期货的到期日与合约乘数、加密的基础币种与合约类型。
instruments 仅数万行，全量载入内存后解析 JSON 无性能顾虑，
换来的是 **schema 稳定：新增市场不改表结构**。

### 关键类型决策

| 决策 | 理由 |
|---|---|
| 价格用 **int64 定点**而非 float64 | **不是为了体积**（实测仅省 6%），而是约束 C5 可复现性：浮点累加顺序不同结果不同，并发海选下无法保证逐笔一致。加密还需跨 13 个数量级的精度 |
| `price_scale` / `qty_scale` 存于 instruments | A 股 1e3 够用，加密需 1e8；每标的自带 scale，引擎按标的解释 |
| `ts_open` / `ts_close` **两端都存** | 数据源惯例相反（Binance kline `[0]` 与 OKX `ts` 均为**开始时刻**），而引擎的时间游标需要的是「信息可得时刻」= 结束时刻。只存一端就要推导另一端，而 A 股日线时长非固定时段（含午休），推导正是未来函数 off-by-one 的高发处。用**字段名**消除歧义，实测代价 +1.22% |
| `trading_day` 与时间戳并存 | 时间戳用于跨市场对齐、加密 24×7、美股夏令时；`trading_day` 用于业务语义。delta 编码后冗余代价近乎为零 |
| 用 `instrument_id` 而非 symbol | 跨市场 symbol 会冲突；4 字节整数比字符串 cache 友好，实测反而净省空间 |

### 明确不纳入数据 schema 的三项

1. **交易规则**（涨跌停、T+1、保证金、最小变动价位）→ 属 `configs/market/*.json`，是 Market 模块配置
2. **复权因子** → 仅对股票 / ETF 有意义。期货的「主力连续」是拼接规则生成的**派生数据**，应作为独立合成标的，与复权无关
3. **多空与杠杆** → 属 Portfolio / Broker 模块

### 目录布局

`data/` 不进 git，因此布局由代码定义、可一键重建 ——
**单一事实源是 [`etl/layout.py`](../etl/layout.py)**，各处不得硬编码路径字符串。

```
data/                                     gitignored
├── bar/market=ashare/freq=1d/year=YYYY/  行情，Hive 分区
├── meta/                                 元数据表（Parquet + CSV 镜像）
│   ├── instruments.parquet  + .csv
│   ├── calendar.parquet     + .csv
│   ├── adj_factor.parquet   + .csv
│   └── corporate_action.parquet + .csv
├── results/                              海选结果，Go 引擎写入
│   └── equity/                           净值曲线分片
├── snapshots/                            引擎状态快照（v0.4）
└── cache/                                ETL 中间缓存，可安全删除
configs/                                  进 git
├── fee/  market/  strategy/
```

一键重建：

```bash
python etl/layout.py
```

### CSV 镜像规则

**元数据表同时输出 CSV 镜像**：Parquet 为权威副本，CSV 仅供人眼检查与 diff。

- 适用范围：仅 `META_TABLES` 四张元数据表；bar 表体量 2000 万行级，**不做镜像**
- **任何程序都不得读取 CSV** —— 它是调试产物，不是数据接口
- 由 `etl/layout.py: write_meta()` 统一写出，避免各处各写一份

### 数据源与格式的分界

```
数据源 ETL 产出  →  Parquet   （data/，gitignored）
人手写的配置     →  JSON      （configs/，进 git）
```

配置用 JSON 而非 YAML：Go 标准库原生支持，无需第三方库；
且 v0.3 的 ParamSpec 需生成 JSON Schema 供 Web 端表单使用，格式统一。

### 一个被省掉的表

原计划的 point-in-time 股票池表**不需要**：BaoStock 停牌日照常返回行，
因此 `bar` 表本身即是 point-in-time 的 ——
`某日股票池 = SELECT DISTINCT instrument_id FROM bar WHERE trading_day = d`。
上市前无行、退市后无行、停牌有行且 `tradestatus=0`，语义完整。

若按每日快照单独存表，7200 × 8000 天 ≈ **5760 万行，比 bar 表还大**，纯浪费。

### v0.1 ✅ — 数据地基（已完成 2026-08-29）

**目标**：拿到干净、可复现、含退市股与 ETF 的本地日线数据集。

- 数据源适配器接口（BaoStock + 新浪两个实现，验证 C9 的可换性）
- 落地「数据存储设计」一节定义的 schema（1 张 bar 表 + 4 张元数据表，
  纯技术面，无估值 / 财务列）：
  - `bar` — 核心 9 列 + A 股扩展列（`preclose` / `turn` / `tradestatus` / `is_st`）
  - `instruments` — 统一列 + `attrs` JSON；含 `price_scale` / `qty_scale`
  - `calendar` — 交易日历
  - `adj_factor` — 复权因子（事件式，见 C2；以 Decimal 解析保 16 位精度）
  - `corporate_action` — 分红送配
- 编码：定点整数 + `DELTA_BINARY_PACKED` + zstd；分区 `market=/freq=/year=`
- 元数据表输出 CSV 镜像（`etl/layout.py: write_meta()`）
- 增量更新 + 断点续传 + 限流退避
- 数据质量校验器：缺失交易日、价格跳变、复权因子突变、量价矛盾、
  **ETF 字段不一致**（新浪部分标的缺 `prevclose`）、
  **退市股双源交叉核对**（BaoStock 337 只 vs AkShare 名单 367 只，见报告第 4 节）、
  **`is_st` 自洽校验**（ST 标记日涨跌幅不应超 ±5%，详见 SCHEMA.md 第 8 节）
- 🟡 **收口项**：ETF 复权方案

> 停牌不再需要独立表 —— BaoStock 的 `tradestatus` 已覆盖，且停牌日照常返回行，
> bar 表可直接与交易日历对齐，同时天然具备 point-in-time 语义。

**验收**：一条命令拉取全量 A 股个股 + ETF 日线落 Parquet，产出质量报告；
Go 侧用 `CoreBar` struct 能正确读回。 **量级 L**

### v0.2 ⭐ — 引擎核心闭环

**目标**：单步状态机 + A 股规则，跑通最简策略。

- `Bar` / `Freq` 多频率时间模型（接口多频率，实现仅日线路径，见 C9）
- `DataGateway`：时间游标，编译期防未来函数（C1）
- Core：`Step() (Event, error)` 状态机（C4）
- `Market`：交易日历、涨跌停计算（基于 `preclose`，见 C8.1）、停牌、T+1
- `Broker`：限价/市价单、一字板拒绝成交、成交量约束、滑点
- `Portfolio`：现金/持仓/冻结/权益/盈亏，除权除息入账
- `Fee`：佣金 + 印花税 + 过户费，**按标的类型分流**（个股 / ETF）
- `Strategy` interface + BuyAndHold + 双均线两个样例策略
- CLI 跑通，输出净值序列

**验收**：手工核算一笔完整交易的费用与持仓，与引擎输出**逐分位一致**；
个股与 ETF 各核算一笔，确认费用模型分流正确。 **量级 L**

### v0.3 — 模块化装配

**目标**：配置驱动装配 + Web 表单的元数据基础。

- registry + `init()` 注册，JSON 配置装配
- **ParamSpec 参数自描述**：策略注册时声明参数名称/类型/范围/步长/默认值

  ```go
  func (s *MACross) Params() []ParamSpec {
      return []ParamSpec{
          {Name: "fast", Type: Int, Default: 5,  Min: 2, Max: 60,  Step: 1},
          {Name: "slow", Type: Int, Default: 20, Min: 5, Max: 250, Step: 1},
      }
  }
  ```

  该机制同时支撑三处：Web 自动生成表单（v0.4/v1.0）、海选自动展开参数网格（v0.6）、配置校验。
- `Sizer` / `Risk` / `Slippage` / `Fee` 全部可替换
- `Recorder` 三档级别（None / Summary / Full）
- 完整指标集：年化收益、夏普、索提诺、最大回撤、卡玛、胜率、盈亏比、换手率、基准超额
- 结果指纹（C5）

**验收**：换 JSON 配置即可改变引擎行为；同配置两次运行结果逐笔一致。 **量级 M**
