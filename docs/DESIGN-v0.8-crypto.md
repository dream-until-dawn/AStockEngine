# v0.8 加密永续：逐仓、双向、按市场计价

> 目标：让加密市场真的能跑回测，且**跑出来的数字是对的**。
>
> v0.3.3 接了加密的数据通道，但交易规则层是空的 —— `checkMarketRules`
> 直接拒绝，宁可不跑也不给一份「看着正常的假结果」。这一版把规则层补上。

约束来自需求方的三句话：**加密固定逐仓 + 双向开仓持仓**、
**计价货币随市场不同**（加密 USDT 默认 1,000，A 股默认 20,000 元）、
**加密基准取 BTC 永续**。

---

## 1. 这一版真正的难点不是「加个市场」

难点是：**这个市场的每一处差异，出错时都不报错。**

A 股与加密的差异不在于「有没有涨跌停」这类能被 `if` 挡住的开关，
而在于一批**量纲**：价格标度 1e3 vs 1e8、数量标度 1 vs 1e8、
合约乘数 1 vs 0.01、年化 243 vs 365、计价单位 元 vs USDT。
量纲错了不会 panic，只会给出一个数量级不对但格式完全正常的数字。

这一版修掉的每一个 bug 都是这个形状。逐个记下来，因为它们不是
「设计能推出来」的，而是**测出来的**。

## 2. 金额与数量：128 位与逐标的 scale

### 2.1 溢出是静默的

`price_fp × qty_fp` 在 BTC 上是 `9.87e11 × 2.53e8 ≈ 2.5e20`，
超过 int64 上限 9.22e18。乘法不报错，只是回绕成一个负数或小数。

`NotionalCents` / `QtyForCents` / `MulDiv` 一律走 `math/bits.Mul64` +
`bits.Div64` 的 128 位中间量。

### 2.2 名义额的换算比不能靠浮点算

`NotionalRatio()` 返回一对整数 `(num, den)`，由合约乘数、价格标度、
数量标度约分而来：A 股 → `1/10`（与旧代码 `price*qty/10` 逐位相同，
由 `TestNotionalMatchesAShareLegacy` 钉住），BTC → `1/1e16`。

合约乘数从 `attrs.ct_val` 读的是字符串 `"0.01"`，**按字符串转定点**，
不经过 float64 —— `0.01 × 1e8` 走浮点得到的是 `999999.9999999999`。

### 2.3 被这一类坑到的三处

| 处 | 症状 | 原因 |
|---|---|---|
| `sizer.go` / `risk.go` | 168 条信号 → 0 笔成交 | `budgetCents * 10 / bar.Close` 是 A 股口径，算出的张数被 `NormalizeQty` 判成 0 |
| `broker.go` 成交量上限 | 114 笔「超出成交量占比上限」的假拒单 | `b.Volume * VolumeCapPPM` = 1.25e22 回绕 |
| 报告 | `未平仓 2 只 / 1352000000 股` | 定点数量直接印，且跨标的相加 —— 不同 scale 的数量相加本身没有意义 |

第三处的修法不是「除以 scale」而是**换一个量**：报告改印
`未平仓 2 只，开仓金额 925.39 USDT`。金额跨标的可加，数量不可加。

## 3. 逐仓与双向：`MarginLedger`

`Ledger` 接口在 v0.3.2 就按保证金账户设计好了（`Exposure` 分多空、
`Mark()` 返回 `[]Liquidation`），当时现货实现里它们恒为空。
这一版填上第二个实现，接口一行没改 —— 这是那次抽象的回报。

### 3.1 逐仓 = 亏损以该仓位的保证金为限

强平时 **保证金全损，余额不动**。测试
`TestMarginIsolatedLiquidationCapsLoss` 钉的就是这一条：
5 倍杠杆下名义额 100.00、保证金 20.00，价格跌 30% 时浮亏 30.00 ——
账户损失必须停在 20.00，可用余额一分不动。

`BuyingPowerCents` 因此是 **余额 × 杠杆**，不是权益 × 杠杆：
已开仓位的浮盈属于那个仓位，拿去开新仓等于把逐仓变回全仓。

### 3.2 双向 = 每个标的两个槽

`long` / `short` 两个 map，不是一个带正负号的净头寸。
「买 100 张」在已有 100 张空单时，单向下是平仓、双向下是开多 ——
意图完全不同，由 `Order.Reduce` 区分。

## 4. 一张表，四个地方 —— `trading.LegOf`

开平方向的映射表：

```
双向：买+开=开多   买+平=平空   卖+开=开空   卖+平=平多
单向：买恒为开多，卖恒为平多（reduce 不看）
```

这张表**原先在四个地方各写了一遍**，而且是逐个被发现的 ——
每修好一个，下一个才暴露出来：

| # | 地方 | 写错的表现 | 怎么发现的 |
|---|---|---|---|
| 1 | `MarginLedger.posFor` | 记错槽位 | 写实现时就想到了 |
| 2 | `metrics` 轮次配对 | 空头轮的盈亏符号相反；平空被当成开多，永远不平 | 报告里 `平均持有 190.8 天` × 314 轮 = 59,911 仓位·日，而 4 槽 × 2432 天只有 9,728 |
| 3 | `sizer` 建仓方向 | **开空变成开多** | 数了一下成交的开平分布：`买开=170 买平=0 卖开=0 卖平=166` —— 一笔空单都没有 |
| 4 | `Composite` union 去重 | **开空信号被平多信号顶掉** | 修完 3 之后再数：`卖开=2`。还是几乎没有 |

第 4 处最隐蔽：`sigKey` 是 `(标的, 买卖方向)`，注释里写着
「真正互斥的是买与卖」—— 在单向市场里完全正确。但双向下
「卖」有两个意思，一多一空两棵镜像的树在 MACD 下穿那一根上
同时发出「平多（卖）」和「开空（卖）」，后者被前者去重掉了。

**四处的共同点：全都不报错。** 所以把表抽成 `trading.LegOf` 一个函数，
四处共用。写在一个地方，改也只用改一个地方。

> 单向市场的口径**一个字没变**：`LegOf(side, reduce, false)` 忽略 `reduce`，
> `sigKey` 退化成 `(标的, 方向)`。`TestUnionSpotStillDedupesBySide` 守这一点。

### 4.1 仓位槽也要分方向

`occupancy` 原先按标的去重，于是「持有 BTC 多头」会挡住「开 BTC 空头」——
那正是双向要做的事。改成 `slotKey{标的, 方向}`，单向下 `short` 恒为 false，
键退化回标的本身。

### 4.2 修完之后

| | 修前 | 修后 |
|---|---|---|
| 开平分布 | 买开 168 / 买平 167 / **卖开 0** / 卖平 166 | 买开 168 / 买平 167 / **卖开 168** / 卖平 166 |
| 信号 | 336 | 669 |
| 轮次 / 平均持有 | 314 轮 / 190.8 天 | 405 轮 / 34.5 天 |
| 总收益 | +146.07% | +129.64% |

收益变低是对的：在一个基准涨了 982% 的市场里补上空头腿，本来就要亏钱。

> **一个我先判错的地方**：最初看到「336 笔成交配出 314 轮」，
> 我说轮次上限应是 168、这证明配对坏了。**这个推理是错的** ——
> 一笔平仓可以吃掉 FIFO 队列里的好几层，每层算一轮，
> 所以轮次多于平仓笔数完全正常。真正的证据是那个
> 190.8 天 × 314 轮的仓位·日数超了槽位上限 6 倍。
> 结论没变，但当时给出的理由不成立。

## 5. 计价与展示：单位不是标签

`Market.Units() (money, qty string)` 进了接口，而不是在报告里按市场名查表。

查表漏一个市场只会安静地印出「元」，而加密账户的余额不是元。
放进接口，新市场不实现就编译不过。

同样的理由，服务端把 `market{impl, money, qty, hedge, annualDays}`
和**每一行自己的 `priceScale` / `qtyScale`** 一起下发，前端照抄，
不按市场名自己判断。

### 5.1 强平消息也是展示

原先印 `强平 7201：buy 253000000 股 @ 613510000000` —— 三个数没一个能读。
改成印**名义额与损失的保证金**：这两个量不需要 scale 就有意义。

## 6. 每个市场自己的默认值

| | A 股 | 加密 |
|---|---|---|
| 初始资金 | 20,000 元 | 1,000 USDT |
| 账本 | `spot` | `margin`（逐仓双向） |
| 市场规则 | `ashare` | `crypto` |
| 基准 | 无（由配置指定 ETF） | `BTC-USDT-SWAP` |
| 年化系数 | 由日历数出（约 242.54） | 365 |

加密的初始资金若沿用 20,000，报告会印「初始 20000.00 USDT」——
数字合法、单位合法、结论全错（20 倍本金起跑）。
`market_defaults_test.go` 把四条都钉住，外加一条
「写了就以写的为准」——默认值最坏的失败方式不是给错，是盖掉用户写的。

## 7. 验收

**加密双向**（`configs/backtest/crypto_hedge.json`，一多一空两棵 MACD 规则树
union 组合，3 倍杠杆 / 4 槽 / 逐仓）：

```
步数 2432   信号 669 条  成交 669 笔  拒单 0 笔
初始 1000.00 USDT → 权益 2296.44 USDT（+129.64%）
开平分布  开多 168 / 平多 166 / 开空 168 / 平空 167
账本告警 1 条：20210203 强平标的 7202：空 仓位，
         名义额 335.73，损失保证金 83.18（逐仓权益 -3.02 低于维持保证金 1.68）
年化系数 365.00   对标 BTC-USDT-SWAP
```

快照往返（第 1200 步）指纹逐位一致 —— `MarginLedger` 的快照/恢复
在真实路径上验过，不只是单测。

**A 股无回归**：三个基线配置的输出指纹**逐位不变**
（`cfa21186f91114e2` / `a988574e5387d7df` / `2bf137b307f9df43`）。
这一版动了 sizer、组合去重、轮次配对三处 A 股必经的代码，
指纹不变才说明「只加了新行为，没改旧行为」。

**服务端**：同一份配置走 API 得到与命令行**相同**的收益与开平分布；
A 股走 API 得到 `元/股 / hedge=false / annualDays=242.54`、
成交方向仍是朴素的「买/卖」（双向的「开多/平多」只在双向市场出现）。
