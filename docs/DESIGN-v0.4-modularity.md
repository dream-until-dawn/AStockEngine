# 模块化的三处补强

> 状态：**已完成**（2026-08-29）
> 起因：一次关于「决策器 / 仓位管理器 / 资金管理器」的讨论

## 提出的诉求与我的判断

原始诉求是加三个平行的「管理器」。我不同意这个**形态**，同意其中两条的**内容**：

| 诉求 | 判断 | 结论 |
|---|---|---|
| 决策器：技术决策与网格决策难以兼容，将来还要接 AI | 真问题，但不在抽象层次 | 加**组合**，不加新的一层 |
| 仓位管理器：多空、保证金、爆仓 | 真问题，而且是唯一还写死单一市场的核心模块 | 抽成 `Ledger` 接口；**实现等有数据再写** |
| 资金管理器：预留资金、多空分桶 | 大部分已经有了 | 不单独成层 |

不加三个平行 Manager 的理由：现在的分层是按**问题的性质**切的，不是按名词切的。

```
Strategy   买什么      Sizer   买多少      Risk   能不能买
Market     何时能成交  Broker  成不成交    Ledger 记账
```

再插三层，第一个日常问题就变成「这条规则该放哪」。

## 1. `Portfolio` → `Ledger` 接口

### 为什么它是真正的障碍

七个模块里六个早就是接口，只有账本还是 struct，而且字段全部导出 ——
任何人都能 `pf.Cash = 999`，「账目自洽」就不再是一条能保证的性质。

更要紧的是它写死了单一市场语义：

```go
if f.Qty > p.Total { return 错误 }   // 空头无从表达
p.Total int64                        // 恒非负
EquityCents = 现金 + Σ 数量×价格     // 没有保证金
                                     // 没有逐步重估的位置，强平无处发生
```

### 接口留出的三处

| 签名 | 留给谁 |
|---|---|
| `Exposure{Long, Short, LongCost, ShortCost}` | 双向持仓。**分多空两边而不是用带符号的净额** —— 有些市场允许同时持有两个方向，净额会把这个信息抹掉 |
| `BuyingPowerCents()` 而非现金 | 保证金账户。撮合问它而不是问现金，问现金就等于假定了现货 |
| `Mark(marks, now) []Liquidation` | 强平。**必须先于策略调用** —— 强平是市场施加的，不是策略的决定 |

外加 `CanFill` ：把「买得起吗 / 卖得出吗」从 Broker 移进账本。
现货不能卖超持仓，保证金账户那叫开空 —— 撮合器不该知道这个区别。

### 只做接口不做实现，是纪律不是偷懒

我们**没有期货和加密的数据**。这个项目一路上每条结论都是数据验出来的：
ETF 份额合并、ST 规则 2026 年变更、滑点该加在哪、标的池偏斜到推翻结论。
照文档写一个验不了的保证金引擎，只会得到一个看起来对的抽象 ——
而保证金与强平恰恰是最容易想当然写错的地方。

C9 的原话就是这条：**接口按多市场设计，实现只做 A 股。**

### 重构的安全网

六个基线配置的**输出指纹逐位一致**。这正是 C5 存在的意义 ——
它把「我觉得没改行为」变成了一个可以验证的命题。

一处被指纹之外的东西抓到的真实差异：`Exposure()` 返回**值拷贝**，
而旧的 `Position()` 返回指针。有个测试先取 `p := pf.Position(id)`、
再做送转、然后断言 `p.Total == 3000` —— 靠的是指针在背后被改。
换成值语义后它挂了，这是**对的**：拿到手的视图不该在背后变，也不该能改账本。

## 2. 策略组合

### 缺的不是「更复杂的策略」

复杂逻辑总能塞进一个 `OnBar`。挡住的是**把不同来源的判断组合起来**：
技术信号 + AI 否决、网格 + 趋势叠加、多模型投票。
共同形态是「N 个独立决策源 + 一套合并规则」，塞进一个策略里
就等于把合并规则也写死了。

所以加的是组合，不是新抽象。**AI 接入就是实现 `Strategy` 的一个源**，
或者挂在 veto 位 —— 不需要为它造一个 `Decider` 接口，
那只会让「Strategy 和 Decider 有什么区别」成为日常问题。

### 三种合并方式

| 模式 | 语义 | 典型用法 |
|---|---|---|
| `union` | 并集，同标的同向保留**靠前**的源 | 主策略 + 补充策略 |
| `confirm` | 交集，所有源同向才发；Strength 取**最小值** | 多模型互相确认 |
| `veto` | 第一个源出信号，后续源的**反向**信号否决它 | AI 覆盖层 |

`confirm` 取最小 Strength：一组判断的可信度不高于其中最弱的那个。

### 一个必须处理的坑：指标命名空间

两个源都 `ic.Use("macd")` 时，引擎的去重会**让第一个赢**，
第二个源静默拿到别人的参数 —— 不报警、不崩溃，结果悄悄不对。

解法是给每个源套一层作用域，指标名加 `s0/` `s1/` 前缀，
而源内部对此毫无感知：它写 `"macd"`，读也写 `"macd"`。
参数同理：一份 `Params` 装不下 N 个源的参数，由组合在 `Init` 时分发。

### veto 的适用条件（实测发现）

`macd_cross + ma_cross` 配 veto，跑出来与 `macd_cross` 单跑**逐位相同** ——
一次否决都没发生。原因不是实现错了（11 个单元测试覆盖了合并规则），
而是这两个策略**结构上不可能互相否决**：

```
macd 买：golden && !held      ma 卖：death && held
```

要 ma 否决 macd 的买，ma 得在同一标的上发卖信号，那要求 `held`；
而 macd 发买要求 `!held`。互斥。

**这是 veto 的适用条件**：否决者必须能在被否决者出信号的同一时点、
同一标的上发出反向信号。像这两个都以「是否持仓」为前置的策略天然做不到。
真正的否决者（AI 覆盖层）不该有这个前置 —— 它只需要说「这笔别做」。

## 3. 网格策略

写它是为了验证一件事：**信号模型能不能表达「非信号驱动」的策略。**

结论：能，靠 `StatefulStrategy` 记两样东西 —— 基准价与当前档位。
两样都无法从 `StepContext` 导出：ctx 只给当前时点，
而基准价是**第一次见到这只标的时**定下的。

### 两处诚实的取舍

**日线上的网格是失真的。** 真实网格靠盘中挂单，一天内可能来回穿好几格；
日线只有一根 OHLC。这里按**收盘价**定档，日内来回全被抹掉 ——
它会系统性**低估**网格的交易次数。用最高最低价去猜穿了几格更不老实：
那等于假设你在最优点位成交。

**基准价一旦定下就不再变。** 让它跟着价格漂移就成了追涨杀跌，不是网格。

### 实测：最低佣金把它吃掉了

`grid` 在 3,193 只在市主板个股上跑（跌 5% 加一格，5 格）：

```
成交 57,010 笔   费用 340,903 元（占初始 34.09%）
  其中 commission 286,048 元 —— 摊到每笔是 5.018 元
滑点 67,909 元   摩擦合计 408,813 元（40.88%）
总收益 +12.13%   超额 −14.18%
```

**每笔佣金恰好是最低的 5 元**，说明每笔成交额都不到 2 万元
（万 2.5 × 2 万 = 5 元）。5.7 万笔 × 5 元 = 28.5 万，
占初始资金 28.5% —— 网格不是被行情打败的，是被最低佣金打败的。

这是配置问题（`strength_weighted` 把 20% 权益摊到几千只标的上，
每笔自然很小），但引擎把它**显示出来了**：费用明细里 commission
远大于 stamp_duty，正是最低佣金档的签名。

## 顺带的三个结果

同一批标的池（在市主板 3,193 只），换合并方式：

| 配置 | 成交 | 收益 | 超额 | 回撤 |
|---|---|---|---|---|
| `macd_cross` 单跑 | 2,090 | +31.92% | +5.61% | 25.95% |
| `composite_union` | 2,385 | +35.50% | +9.19% | 24.20% |
| `composite_confirm` | **92** | **+53.43%** | **+27.12%** | 28.42% |
| `composite_veto` | 2,090 | +31.92% | +5.61% | 25.95% |
| `grid` | 57,010 | +12.13% | −14.18% | 27.68% |

`confirm` 只成交 92 笔却是最好的一档。这与整个项目一路的观察一致：
**摩擦是这些高换手策略的主要杀手**。但 92 笔的样本太小，
不能据此说 confirm 更好 —— 那正是 v0.5 海选要用 IS/OOS 与
参数高原去回答的问题。
