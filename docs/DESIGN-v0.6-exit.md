# 离场规则 —— 止损、止盈、移动止损

> 2026-08-30。起因：「风控上，高点回落是有，但没有止盈止损啊？」

---

## 0. 缺口是真的

v0.3 之前有 5 条风控，全是**开仓限制**：

| 规则 | 它做什么 |
|---|---|
| `max_position_pct` | 单只标的市值占权益的上限 |
| `max_positions` | 最多同时持有几只 |
| `cash_reserve` | 留一部分现金不参与买入 |
| `min_turnover` | 成交额太低的不开新仓 |
| `drawdown_halt` | 自峰值权益回撤超阈值后**停止开新仓** |

最后一条容易被当成止损，但它是**账户级**的，而且**不平任何持仓** ——
它只是不让你再买。逐仓的「这只亏了 8% 就割」一条都没有。

---

## 1. 为什么它不能是一条 Risk

```go
type Risk interface {
    Check(o Order, ctx RiskContext) (Order, Rejection, bool)
}
```

**订单进、订单出。** 这是个过滤器 —— 它只能把已有的订单缩量或拒掉。
而止损要**产生**一张卖单。硬塞只有两条路，都不行：

- 让 `Check` 额外返回新订单 → 它就不再是过滤器，链式语义
  （「任一条拒绝即拒绝，通过的可被前一条缩量后传给下一条」）随之崩掉
- 在别处偷偷下单 → 绕过了 Sizer 与整条 Risk 链

---

## 2. 为什么它也不该是一个 Strategy

组合策略（`Composite`）确实能把它当决策源接进来，但：

**① 优先级保证不了。** 止损必须压过策略的判断 ——
策略说「继续持有」时止损也要能平掉。`union` 是先到先得，
靠源的书写顺序来保证优先级太脆弱；`confirm` 要求全体同意、
`veto` 只让第一个源下单，两者直接把止损废掉。

**② 性质不同。** 止损是风险管理，不是 alpha。混进策略组合，
「这个收益是策略赚的还是止损救的」就归因不清了。

---

## 3. 于是：第三类决策来源

```go
type ExitRule interface {
    Name() string
    OnStep(ctx ExitContext) []Signal
}
```

在引擎里排**第 5.5 步**，在策略之前：

```
4.  撮合到期订单
4.5 账本重估 → 强平（市场施加的）
5.  权益快照
5.5 离场规则 → 离场信号        ← 新增
6.  策略 → 信号
    mergeExits：离场信号覆盖策略在同一标的上的信号
7.  Sizer → 订单
8.  Risk 链 → 入队
```

`mergeExits` 会**丢掉策略在同一标的上的信号**。不丢的话会出现
「策略要加仓、止损要清仓，两张单一起进 Sizer」，
或者两条卖单叠在一起、第二张必然因无券可卖被拒。

> 与 `Ledger.Mark()` 的强平形状相似但性质不同：
> 强平是市场施加的（保证金不足），离场是自己事先定好的。
> 分开记，归因才清楚。

## 4. 三条实现

| 名字 | 参数 | 触发条件 |
|---|---|---|
| `stop_loss` | `pct` | 市值/成本 ≤ 1 − pct% |
| `take_profit` | `pct` | 市值/成本 ≥ 1 + pct% |
| `trailing_stop` | `pct` / `arm_pct` | 自持仓期间峰值回落 pct%，盈利达 arm_pct% 后才启用 |

### 4.1 移动止损盯的是「盈亏比」不是价格

峰值记的是 **市值 / 成本**，不是收盘价。理由是它对**送转与部分卖出
都免疫**：

- 送转时 qty 与每股成本同时变，比值不变
- 部分卖出时市值与成本同比例缩，比值也不变

若直接记价格，一次 10 送 10 就会让峰值凭空高一倍，
移动止损当天必然触发 —— 而那一天什么也没发生。

无公司行动、无部分卖出时它与教科书定义**完全等价**：
比值 = 现价 / 均价，回落 x% 即现价自峰值回落 x%。

### 4.2 `arm_pct` 不是可有可无的

没有它，刚建仓就被一点回撤扫出去，移动止损成了「买入即卖出」。

### 4.3 峰值必须进快照

`TrailingStop` 实现 `StatefulExit`，峰值随引擎快照一起存。
不存的话，从快照恢复后峰值归零，**移动止损静默失效** ——
不报错、不异常，只是再也不会触发。而 C6 的实盘模式**每天都从快照恢复**。

## 5. 三条不发信号的情形

`eachSellable` 会跳过：

| 情形 | 为什么 |
|---|---|
| `Available == 0` | T+1 锁着。发了只会得到一条「无券可卖」的拒单，**而且每天重发**。买入次日触发止损是真实存在的情形 —— 那一天你确实卖不掉 |
| 已有在途单 | 重复下单，第二张必然被拒 |
| 无 bar / 停牌 / 零成交 | 撮合不了 |

成本用 `Exposure.LongCost`（**实际付出的钱**）而不是复权价推算：
送转会同时改变 qty 与每股成本，用钱算天然对。
但**收到的现金分红不冲减 LongCost**，所以高分红标的的止损会略偏保守 ——
这是已知的口径，写在这里。

## 6. 实测

`macd_full`（3,376 只主板个股含退市，2020 起，`slots=10`）：

| 离场规则 | 成交 | 轮次 | 总收益 | 最大回撤 | 夏普 |
|---|---|---|---|---|---|
| 无 | 1,424 | 709 | −29.66% | 55.71% | −0.188 |
| 止损 8% | 1,788 | 892 | −34.08% | 46.53% | −0.238 |
| 止损 8% + 止盈 25% | 2,436 | 1,214 | **+35.08%** | **28.73%** | 0.291 |
| 移动止损 10%（盈 5% 后启用） | 1,988 | 990 | +14.58% | 26.46% | 0.107 |

### ⚠ 这几个数字要放在噪声基线下读

**这个配置的噪声基线是 18.95 个百分点**（`slots=10`，见
[DESIGN-v0.5-selection.md](DESIGN-v0.5-selection.md) §0）。所以：

| 对比 | 差值 | 判断 |
|---|---|---|
| 止损 8% vs 无 | −4.42 pp | **在噪声内，不可分辨** |
| 止损+止盈 vs 无 | +64.74 pp | 远超噪声（约 9σ），方向可信 |
| 移动止损 vs 无 | +44.24 pp | 超过噪声，方向可信 |

**「止损单独用反而更差」这句话不能说** —— 4.42 个百分点完全在
同一配置的随机抖动里。而后两条虽然量级很大，仍然是 **n=1 的单次对比**，
正确的做法是把 `exit.*.pct` 扫进 v0.5 的参数网格，
看 18 个 OOS 窗口的分布。

最大回撤的改善（55.71% → 26~29%）是三条里最一致的，
且它的机制是直接的（一亏到阈值就砍），比收益的改善更可信。
