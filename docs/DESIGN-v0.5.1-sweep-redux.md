# v0.5.1 海选（草稿）—— 重新对准现在的引擎

> [DESIGN-v0.5-selection.md](DESIGN-v0.5-selection.md) 的方法论**一条都不推翻**：
> 先量噪声、再判「参数有没有可辨别的影响」、最后才谈高原；
> 输出稳健区域而不是 top-1。
>
> 但那份设计瞄准的是 v0.5 当时的引擎，而引擎从那以后动了很多。
> 这份草稿只谈**差在哪、要补什么**。

---

## 0. 先说三件已经不成立的事

### ① 现成的海选配置跑不起来

```
$ go run ./cmd/sweep -config ../configs/sweep/macd_coarse.json
错误: 读取配置 ..\configs\backtest\macd_history.json 失败: 找不到文件
```

`macd_coarse.json` 的 `base` 指向 `macd_history.json`，而那份配置在
v0.8.5 收敛默认配置时删掉了。这是最表面的一层。

### ② 网格瞄准的是一个已经退居二线的策略

```json
"grid": {
  "strategy.params.short": [5, 8, 12, 16, 20],
  "strategy.params.long":  [20, 26, 34, 45, 60],
  ...
}
```

`macd_cross` 现在是 legacy —— 装配器里已经不提供了，主力是**规则树**。
而规则树的参数不是 `strategy.params.short` 这样的标量，
是 `strategy.params.indicators[0].params.short` 这样**藏在数组里的结构**。

`setPath` 只认 `map[string]any`，遇到数组直接报「不是对象，无法继续往下写」。
**所以现在的网格机制够不着规则树的任何一个参数。**

### ③ 噪声基线是在另一套口径下测的 —— 它是整个方法论的地基

原来的数字：初始资金 ±0.1% 扰动下，`slots=10` 的收益跨度 **18.95pp**、
`slots=100` 是 4.48pp（非单调，`slots=30` 反而是 27.08pp）。

那是在这套口径下测的：

| | 测噪声时 | 现在 |
|---|---|---|
| 定量基准 | `initial`（定额下注） | `cost`（已投入本金） |
| 候选排序 | 标的 ID 升序 | 当日成交额降序 |
| 定量是否留摩擦 | 否 | 是 |
| 被测策略 | `macd_cross` | 规则树 |

四条全变了，而**整个 v0.5 的判据就是「全网格的散布有没有超过噪声地基」**。
地基挪了，上面所有的高原结论都得重算。

> 这不是「顺手复测一下」，这是**第一刀**。
> 拿旧地基去判新网格，会得到一个看上去很确定、实际没有依据的结论 ——
> 而那正是这套方法论建来防的东西。

### 重测结果（2026-08-30，刀一已做）

新口径下（定量基准 `cost`、候选按成交额排、定量留摩擦、策略是规则树）：

| 标的池 | slots | 标准差 | 极差 |
|---|---|---|---|
| A 股主板在市个股（2015–2026，8 窗） | 10 | **3.32 pp** | **8.99 pp** |
| 同上 | 100 | **0.19 pp** | **0.55 pp** |
| 加密单标的 BTC（2020–2026，10 窗） | —（单标的） | **4.24 pp** | **11.13 pp** |

对照旧口径：`slots=10` 极差 18.95 pp、`slots=100` 4.48 pp。

**量级小了一半以上，但两条结论一条没变**：

1. 噪声仍然大到足以吞掉多数参数差异 —— A 股 slots=10 时，
   两组参数差 8 个百分点以内都不能说谁更好
2. 噪声仍然随 slots 急剧下降，而且比从前更陡：
   旧口径 10→100 是 4 倍，新口径是 **16 倍**

> ⚠ **这不是一次受控对照**：旧数字用的是 `macd_cross` 且覆盖 2005 年起的
> 全历史，新数字是规则树、2015 年起。口径和样本同时变了，
> 所以只能说「新口径下的地基是这个数」，不能说「是这四条改动把噪声压下去的」。
> 要归因得单独做，而目前没有必要 —— 需要的只是一个**当下有效的地基**。

## 0.5 第一轮真跑（2026-08-30）

六份海选，合计 **约 4.5 分钟**（加密两份 106 秒，A 股四份 166 秒）。
成本几乎全在载数据：A 股全量载入约 30 秒，而跑批本身
1,496 次回测只要 2 秒。

| 海选 | 组数 | 窗口 | 噪声极差 | 网格散布 | 比值 | 判定 |
|---|---|---|---|---|---|---|
| 加密单标的 BTC | 2,187 | 10 | 7.02 | 6.64 | **2.69×** | 有影响 |
| 加密多标的双向 | 2,187 | 10 | 8.44 | 2.52 | **0.84×** | **不可分辨** |
| A 股 601318 平安 | 243 | 8 | 0.12 | 4.59 | 116.71× | 有影响 |
| A 股 600036 招行 | 243 | 8 | 1.44 | 2.06 | 3.82× | 有影响 |
| A 股 000001 平安银行 | 243 | 8 | 6.39 | 3.95 | **1.79×** | 有影响（勉强） |
| A 股 12 只小池 | 729 | 8 | 1.25 | 1.60 | 3.35× | 有影响 |

**六份里没有一份找到稳健区域。** 判据（邻居 ≥ 6、邻域 OOS 中位数 > 0、
正的比例 ≥ 60%、IQR ≤ 3× 噪声）一条都没被同时满足。
按方法论，这就是结论 —— 不是失败。

### 跑出来才发现的一条：排名被「一个走运的窗口」占据

第一轮的前五名**全都只有 1 个窗口**，而且不同参数组的 OOS 中位数
一模一样 —— 它们活下来的是同一个窗口，在那个窗口里这些参数根本没起作用。

原因：`Aggregate` 只要求「至少有一个窗口过了硬门槛」。
一组参数在 8 个窗口里被门槛筛掉 7 个，剩下那一个的收益就成了它的
「OOS 中位数」，然后拿去和跑满 8 个窗口的参数并排比。

加了**窗口覆盖率下限**（60%，`MinWindowCoveragePPM`）之后：

| 海选 | 散布（修前 → 修后） | 比值（修前 → 修后） |
|---|---|---|
| 加密单标的 | 9.14 → **6.64** | 3.71 → 2.69 |
| A 股 601318 | 6.77 → **4.59** | 172 → 117 |
| A 股 600036 | 7.51 → **2.06** | 13.9 → 3.82 |
| A 股 000001 | 7.07 → **3.95** | 3.20 → 1.79 |
| A 股 12 只小池 | 3.72 → **1.60** | 7.77 → 3.35 |

**散布削掉三成到六成** —— 也就是说，之前那部分「参数有影响」
是一两个走运窗口贡献的。`000001` 从 3.20× 掉到 1.79×，
已经贴着 1.5 的判定阈值。

被剔掉的比例高得惊人：A 股小池 **594 / 729 组（81%）**、
601318 **207 / 243（85%）**。报告现在会把这个数印出来 ——
不印的话，参与排名的组数会莫名其妙地少一大截。

### 另外两条值得记下的

- **加密双向那份是唯一判定「不可分辨」的**（0.84×）。
  它扫的是熔断的三个轴（阈值 / 冷静期 / 杠杆），散布 2.52 而噪声 8.44 ——
  在双向 + 熔断这套组合下，这些轴的影响还不如初始资金抖 0.1%。
- **有些轴是完全惰性的**：A 股小池的前五名里，`exit[0].params.pct`
  取 10 / 15 / 25、`valid.right.value` 取 70 / 80，OOS 中位数
  一模一样（−7.70%）。止损线和有效性阈值在这个配置下从没起过作用 ——
  下一轮该把它们换成别的取值范围，或者干脆撤掉这两个轴。

## 1. 规则树怎么扫

分三层，按「成本」和「有多容易骗到自己」排。

### 层一 · 数值轴（本刀做）

树的**形状固定**，只扫里面的数字：

```json
"grid": {
  "strategy.params.indicators[0].params.short":  [8, 12, 16],
  "strategy.params.indicators[0].params.long":   [26, 34, 45],
  "strategy.params.indicators[1].params.period": [9, 14, 21],
  "strategy.params.valid.right.value":           [60, 70, 80],
  "sizer.params.slots":                          [5, 10, 20],
  "exit[0].params.pct":                          [8, 15, 25]
}
```

要补的只有一件事：**`setPath` 支持 `[i]` 下标**。二十来行，
沿用它现在的严格性 —— 路径指不到就报错，不新建字段
（「新增多半是写错了名字」这条保留）。

### 层二 · 子树开关（本刀做，便宜，而且回答一个真问题）

一个布尔轴，在「挂着这棵子树」与「整棵拿掉」之间切：

```json
"toggles": {
  "strategy.params.valid": [null, {"left": {...}, "cmp": "lt", "right": {...}}]
}
```

它直接回答**「有效性树值不值得留」**—— 而这个问题现在已经有对照数据了：
逐轮交易里虚拟轮次与实仓并排（实测 `crypto` 上实仓 152 轮平均 +3.87%、
被过滤的 13 轮平均 −1.78%）。海选把它变成跨 18 个窗口的统计，
而不是一次运行的巧合。

止盈、止损、熔断同理：`exit` / `risk` 数组的**有无**本身就是一个轴。

### 层三 · 结构枚举（暂缓，已拍板）

枚举「哪些条件组成买入树」是组合爆炸，而且是整个系统里**最容易过拟合**
的一件事 —— 条件库有 20 个候选、树深 3 层，搜索空间就足以让任意样本
上都能找出一棵「很好」的树。

先把层一层二跑通、看清噪声地基有多高，再谈要不要碰它。

## 2. 新出现的轴

自 v0.5 之后加进来的，全都该进网格：

| 模块 | 轴 | 为什么值得扫 |
|---|---|---|
| `sizer` | `base`（cost / notional / equity） | 实测：杠杆只有在 `notional` 下才放大敞口 |
| | `order_by`（amount / volume / signal） | 实测：A 股上三种差 6pp，加密上差 17pp |
| | `fit_cash` | 实测：打开后 `macd_cross` 从 +17.85% 变 −17.01% |
| | `slots` | v0.5 就说过它对噪声的影响比多数策略参数都大 |
| `exit` | `stop_loss.pct` / `take_profit.pct` / `trailing_stop.pct` | —— |
| `risk` | `drawdown_halt.pct` / `cooldown_bars` / `flatten` | 冷静期是新的，没测过 |
| | `min_capital.floor` | —— |
| 加密 | `portfolio.leverage` / `maint_margin_ppm` | 实测：维持保证金率 0.1%→10% 时强平 6→52 次、收益 +123%→+18% |

> **`fit_cash` 与 `order_by` 要单独扫一遍再进大网格。**
> 它们不是策略参数，是**口径**；混在一起扫的话，
> 「哪个维度在起作用」会归因不清 —— 这正是 v0.5 §11⑥
> 决定「第一刀先只跑一个策略」的同一条理由。

## 3. 切窗必须按市场分

原设计：IS 3 年 / OOS 1 年 / 步进 1 年 → A 股 5,260 个交易日切出 **18 个窗口**。

加密不行：数据从 2019-11 起，到今天 **2,432 个交易日 ≈ 6.66 年**。
同样的参数只切得出

```
floor((6.66 − 3 − 1) / 1) + 1 = 3 个窗口
```

**三个窗口什么也证明不了。** 加密要另一套：IS 1.5 年 / OOS 0.5 年 / 步进 0.5 年 → **10 个窗口**
（`floor((6.66 − 1.5 − 0.5) / 0.5) + 1`）。

要补两件事：

1. 窗口参数**按市场给默认值**（与初始资金、账本、年化系数同一条路子）
2. **窗口数下限保护**：切出来少于 N 个（建议 6）就直接报错，
   而不是安静地跑出一份「基于 3 个窗口」的高原结论。
   少于 6 个窗口的 OOS 中位数与 IQR 没有意义，而报告不会告诉你这一点

## 4. 判据要用上新拿到的信号

排名仍用 `excess_over_maxdd`，但**筛掉的条件**要加几条 ——
它们都指向同一类自欺：「这个结果不是策略挣来的」。

| 新判据 | 拦的是什么 |
|---|---|
| 强平次数占比 | 高杠杆下**强平在替你止损**（实测杠杆 20 收益反而更高，139 次强平）。这不是边际，是运气 |
| 熔断清仓次数 | 同理：收益来自风控而不是信号，换个市场就没了 |
| 摩擦 / 初始资金 | 实测 A 股两万本金切 10 份时摩擦吃掉 47% —— 5 元最低佣金咬到两万成交额为止。摩擦占比高的组，比的是费率不是策略 |
| 虚拟轮次 − 实仓轮次 收益率差 | 有效性树到底在过滤什么。差值为负才说明它该留 |
| 未平仓开仓金额占比 | 收益挂在没结算的浮盈上 |

前三条建议做成**硬门槛**（与现有的 `min_round_trips` 并列），
后两条进结果表供排序，不硬拦。

### 刀三落地记录（2026-08-30）

#### 子树开关**不用建**，现成的网格已经支持

`decodeNumbers` 用的是 `json.Decoder.UseNumber()` 解进 `[]any` ——
它本来就吃任意 JSON 值。所以下面这两种轴直接就能写：

```json
"strategy.params.valid": [null, {"left": …, "cmp": "lt", "right": {"value": 70}}],
"exit": [[], [{"impl": "stop_loss", "params": {"pct": 15}}]]
```

`null` = 把这棵有效性树整棵拿掉；`[]` = 不挂任何离场规则。
两条都由 `TestExpandSubtreeToggle` / `TestExpandToggleWholeChain` 钉住。

#### 但高原分析对它们无能为力 —— 所以补了「逐维边际」

高原要「邻居」，而邻居要求维度是**有序的数**。混进一个非数值轴，
几何反推整个失败：

	⚠ 网格几何反推失败（维度 "exit" 的取值不是数（[]）——
	  非数值维度无法定义「邻居」，也就谈不上高原）

这个报错本身是对的，但它意味着「这棵树值不值得留」这个问题反而没人回答。

补上**逐维边际**：把参数按某一维的取值分组，各看各的 OOS 中位数。
它答不了「哪片区域稳健」，但答得了「这个轴有没有用、往哪边用」，
而且不需要有序。实测一次就问出了东西：

| 轴 | 取值 | OOS 中位数 |
|---|---|---|
| `exit`（止损链） | 有 / 无 | **−5.06% / −5.06%** |
| `strategy.params.valid` | 无 / 阈值 70 / 阈值 80 | **−5.06% 三个全同** |
| `indicators[0].params.long` | 26 / 34 / 45 | **−7.70% / −5.06% / −3.37%** |

**止损链和有效性树在这个配置下从没起过作用**；`long` 是唯一有影响的轴，
而且单调。这两条从收益本身一个字也看不出来。

> 边际视图**放在高原之前**输出 —— 几何反推失败会 return，
> 放在后面的话非数值轴连一个数字都拿不到。第一版就是这么写错的。

#### 判据落地

结果表新增七列：`liquidations` / `halt_exits` / `stop_exits` /
`friction_ratio` / `open_cost_ratio` / `virtual_trips` / `virtual_edge`。

前三条进硬门槛（`max_liquidation_ratio` / `max_halt_exit_ratio` /
`max_friction_ratio`，都默认 0 = 不限），门槛拦下的原因**按类别分开报** ——
只报一个总数的话，「是轮次太少还是强平太多」看不出来，
而这两者要采取的行动完全不同：前者该放宽门槛或换更长的窗口，后者该降杠杆。

`virtual_edge` = **实仓逐轮收益率 − 虚拟逐轮收益率**，为正才说明那棵
有效性树该留。两边都用逐轮口径（每轮的收益率再取平均），
不是总盈亏除以总成本 —— 后者被大额轮次主导，与虚拟那边的逐笔价差口径对不上。
为此给 `TradeStats` 补了 `AvgReturnRatio`。

### 轴的第二轮：上一轮「两个轴惰性」的结论是错的

第一轮的逐维边际说：止损链有无、有效性树三档，OOS 中位数**一模一样**。
查下来两条各有各的原因，而第二条更要紧。

#### ① 止损 15% 在 11.65 年里只触发过 1 次

直接对比（全样本，A 股 12 只小池）：

| 变体 | 收益 | 轮次 | 离场 |
|---|---|---|---|
| 无有效性树 | +13.89% | 289 | 卖出信号 289 |
| RSI<70 | **+19.67%** | 286 | 卖出信号 286 |
| 止损 15% | +13.89% | 289 | **止损 1** |
| 止损 5% | +13.93% | 302 | 止损 49 |
| 止损 3% | +7.73% | 322 | 止损 119 |

买入树带「在 60 日线之上」的趋势过滤、卖出树是「跌破 60 日线」——
**趋势出场总是先到**，15% 的止损根本轮不到它触发。活的区间是 3~8%。

#### ② 有效性树根本不惰性 —— 是硬门槛造出来的假象

同一张表里 RSI<70 比不过滤高 **5.8 个百分点**。那第一轮为什么三档全同？

因为硬门槛设成了「每个 1 年窗口 ≥ 30 轮」，而这份配置**全样本每年只有
约 24.8 轮**（289 轮 ÷ 11.65 年，slots=5）。门槛比典型年份还高 ——
92%（198/216）的参数组因窗口覆盖不足退出排名，
逐维边际就算在剩下那 18 组上，一个偏窄且不具代表性的子集。

**那个错误结论没有任何地方报错，它只是看上去很确定。**

修法两条：

- 门槛按「全样本每窗口典型轮次的一半」定，六份配置全部重校
  （加密单标的 5→3、加密双向 5→10、A 股单标的 10→4、A 股小池 30→10）
- 报告在窗口覆盖不足的比例超过 50% 时**直接警告**，并说清楚
  「下面的排名与逐维边际都只算在活下来的那些组上」，以及怎么定门槛

#### 重跑之后的真实结论

门槛降到 10、止损换成 4/6/8% 之后（432 组全部参与排名，止损触发 6,596 次）：

| 轴 | 取值 → OOS 中位数 | 跨度 | 判断 |
|---|---|---|---|
| `sizer.params.slots` | 3 → −6.27%，5 → −4.67%，8 → −2.58% | **3.69pp** | 最强，单调 |
| `strategy.params.valid` | 60 → −2.66%，70 → −4.42%，80 → −5.01%，无 → −5.01% | **2.35pp** | 单调，越严越好 |
| `strategy…long` | 26 → −3.88%，34 → −4.53%，45 → −4.10% | 0.65pp | ≈ 噪声（0.60），惰性 |
| `strategy…short` | 8 → −4.01%，12 → −4.53%，16 → −3.77% | 0.76pp | ≈ 噪声，惰性 |
| `exit`（止损链） | 有 → −4.10%，无 → −3.92% | 0.18pp | **远低于噪声，不可分辨** |

三条值得记：

1. **`slots` 与 `valid` 才是活的轴**，而第一轮说「唯一有影响的是 `long`」——
   完全相反。差别只在门槛校准
2. **`valid` 的 80 档 ≈ 不过滤**（−5.01% 两者相同）—— 这些大盘股的 RSI
   很少上到 80，阈值定在那儿等于没定。60 才真正在过滤
3. **止损触发了 6,596 次，对 OOS 中位数的影响却只有 0.18 个百分点**，
   低于噪声基线 0.60。它在做事，但做的事不改变结果

六份海选重跑后仍然**没有一片稳健区域**。加密单标的的头名有
9/10 个窗口、OOS 中位数 +13.61%、正的比例 67% —— 是六份里最像样的一个，
但邻域的四分位距过不了「≤ 3× 噪声」那一关。

## 8. 按标的海选：A 股 ETF 网格（实测）

第一次真正按「重复维度 = 标的」跑的海选。目标是你问的三个问题：
**网格分几层、间距多少、止损线定在哪。**

配置 `configs/sweep/etf_grid.json`：12 只 ETF（按不同收益驱动挑，
共同起点 20170803）× `levels{3,5,8,12}` × `step_pct{2,3,5,8,12}` ×
`stop_levels{0,2,4,8}` × `本金{10万,50万,200万}` = 240 组 × 12 只 = 2880 次，
跑完 7 秒。

### 8.1 跑之前先修的四个洞

这一轮的价值有一半在这里 —— **前三个洞都不报错，只是安静地答非所问**。

| # | 洞 | 症状 | 真相 |
|---|---|---|---|
| 1 | `Grid.targetLevel` 的**符号反了** | 网格「跑得挺好」，止损一次不触发 | 做多网格跌 3 格返回 `+3`，而 `target()` 认为 `+3` 是「涨上去该减仓」—— **整张网跑成了越跌卖得越多的追涨杀跌**。而且价格涨到 anchor 之上时它一律返回 0，网的上半边根本不存在 |
| 2 | 基准**绑在 DataSet 上**，每个 Job 的 `metrics.benchmark` 到不了 | 12 只 ETF 的「超额」全是跟 510050 比 | 12 只算出来的基准收益一模一样都是 `+32.32%`。「比一直拿着这只 ETF 强多少」被悄悄换成了「比一直拿着上证 50 强多少」 |
| 3 | 噪声探针的初始资金**写死 1,000,000 元** | 基线看着挺小 | 基准配置写 10 万本金时，探针实际在 100 万本金下跑 —— 量出来的基线不属于它要衡量的那批结果。已改成**倍率**扰动，顺带让本金本身能当网格的一个轴 |
| 4 | `StopExits` 只数风控引擎的两个 tag | 「止损 0 轮」一直挂着 | 网格自己的 `grid_stop` 没被数。止损线定在哪是这次要回答的问题之一，答不了那个轴就是摆设 |

第 1 个洞最值得记：`targetLevel` 和 `target` **各自都有单元测试、各自都是绿的**，
因为它们各自用的是**相反**的符号约定，而没有任何一个测试同时看见两边。
补上的 `TestGridFallingPriceBuysMore` 直接测那句唯一要保证的话 ——
**价格越低，仓位越重** —— 一个跨函数的断言顶十个各自为政的。

### 8.2 按标的海选与按窗口海选，判据必须换

跨标的的离散**天然就大**：黄金 ETF 与创业板 ETF 九年下来收益差几倍，
那是标的本身的差别，不是参数不稳。拿「IQR ≤ 3× 噪声」去卡，
等于要求同一组参数在黄金和创业板上给出几乎相同的收益 ——
那永远过不了，而且过不了也说明不了任何事。故 `PerSymbolCriteria()`
去掉离散度那一条，只留「邻居数 / 中位数 > 0 / 正的比例」。

汇总口径也必须换成**超额**（`Config.MetricOf()`）。同一批结果：

| 口径 | 中位数 | 三个轴的走向 |
|---|---|---|
| 绝对收益 | **+33%** | 全都指向「少交易、多持有、别止损」 |
| 超额 | **−3.5%** | 出现内点最优 |

绝对收益口径下排出来的第一名只是「哪只 ETF 九年涨得多」，与参数无关。

### 8.3 结果

噪声基线 1.60 个百分点，全网格散布 10.89 —— 比值 6.82×，**参数确有影响**。

逐维边际（超额中位数）：

| 轴 | 取值 → 超额中位数 | 读法 |
|---|---|---|
| `levels` | 3 −11.1% / **5 −5.5%** / **8 −5.3%** / 12 −13.5% | 内点最优，**5~8 层** |
| `step_pct` | 2 −20.2% / 3 −10.4% / **5 −4.2%** / **8 −4.7%** / 12 −10.8% | 内点最优，**5~8%** |
| `stop_levels` | **0 −4.1%** / 2 −15.5% / 4 −12.8% / 8 −7.4% | 单调，**不设止损最好**；非要设就设远 |
| 本金 | 10万 −7.8% / 50万 −6.8% / 200万 −6.8% | 约 1 个百分点 |

本金那一轴是为了**排除混淆**加的：A 股 ETF 免印花税与过户费，只付佣金
万 2.5、**最低 5 元**，而 10 万本金切 24 份时每格才 4,167 元 ——
实测隐含单边佣金率 **26~82 bps，名义只有 2.5 bps**（`levels` 越大越糟）。
但扫出来它只值约 1 个百分点：费率倍数很吓人，绝对影响不大，因为换手本来就低。
**先量再说，不要靠推理定量级。**

### 8.4 真正的结论：网格挑的是行情，不是参数

没有任何一片区域满足「邻域中位数 > 0 且正的比例 ≥ 75%」。
最好的单组是 `levels=5, step_pct=5, stop_levels=0`，超额中位数 +6.0%，
但**只在 12 只里的 7 只上赢**。

逐标的摊开之后，模式一眼可见：

| 标的 | 买入持有 | 网格超额中位数 | 赢面 |
|---|---|---|---|
| 513050 中概 | −23.2% | +10.8% | 88% |
| 512880 证券 | +3.1% | +42.0% | 90% |
| 159920 恒生 | +5.8% | +16.3% | 88% |
| 512100 中证1000 | +37.4% | **+123.6%** | 100% |
| 510050 上证50 | +32.3% | −1.8% | 38% |
| 512800 银行 | +63.6% | −42.9% | **0%** |
| 159915 创业板 | +108.5% | −49.3% | 0.8% |
| 518880 黄金 | +246.9% | −187.3% | **0%** |
| 159941 纳指 | +411.1% | **−415.6%** | **0%** |

**corr(买入持有收益, 网格超额中位数) = −0.937。**

买入持有超过 +50% 的四只，网格赢面全是 0 —— 一组都没有。
159941 那个 −415% 不是亏了 4 倍，是「买入持有 +411%，网格约 0%」：
网格一路卖上去，最后空着手看着它涨。

**你说个股「可能会出现长单边行情」所以不适合网格 —— 这条对 ETF 一样成立**，
而且是这次海选唯一足够强的结论。层数、间距、止损线三个轴加起来能挪动
十几个百分点，选对标的能挪动几百个。**参数选优的天花板远低于选品。**

### 8.5 遗留

- 逐标的表目前只在 CLI 里，Web 的海选视图还没有这一屏
- `stop_levels` 单调指向「不设止损」，但那是在**日线收盘定档**这个失真前提下的结论 ——
  真实网格靠盘中挂单，止损的作用可能被系统性低估
- 未平仓开仓金额占比 81.9%：网格天然一直持仓，这个数高是结构性的不是异常，
  但它意味着结果对末期价格敏感

## 9. 「哪只标的配哪套网格参数」—— 走完一遍，答案是不能

第 8 节的结论是「网格挑的是行情不是参数」，于是下一个自然的问题是：
**那能不能按标的的形态，给每只标的配一套自己的参数？**
这一节把它当成一个可证伪的命题跑完了。结论是**不能**，而且不能的方式很干净。

### 9.1 先修一个自己犯的错

第 8 节报了 `corr(买入持有收益, 网格超额) = −0.937` 并把它当成
「网格挑行情」的证据。**那一步是错的，那个相关系数几乎全是算术必然。**

实测同一批数据：`corr(基准收益, 策略收益) = −0.056`，
而 σ(基准收益) = 125.3%、σ(策略收益) = 47.6%。于是

```
corr(bench, bench − strat) ≈ −σ_bench / √(σ_strat² + σ_bench²)
                            = −125.3 / √(47.6² + 125.3²) = −0.935
```

—— 与实测的 −0.937 吻合到小数点后两位。

真正的事实更简单也更强：**网格的收益与标的自己涨多少几乎无关。**
标的涨得越多、你放弃得越多，这不是参数没选好，这是网格的定义。

教训：**一个很大的相关系数，先算一遍它在零假设下会是多少。**

### 9.2 标的池：69 只去重 ETF

`etl/etf_character.py`。1651 只 ETF → 覆盖 2017-08 至今且日成交额中位数
≥ 1000 万的 111 只 → 剔掉货币 / 短债（年化波动率 < 10%）剩 93 只 →
按日收益相关 ≥ 0.95 合并影子标的，**剩 69 只**。

沪深300 一只吞掉了八只壳（510050 / 159919 / 510330 / 510310 / 510180 /
510360 / 512990 / 159925）。不合并的话横截面里同一个样本被数了九遍。

**货币 ETF 那条必须写死在脚本里**：它们价格恒定 100 元、收益靠每日分红发出去，
「净位移 ÷ 总路程」算出来接近 0 —— 在效率比榜上排「最震荡」第一名，
而它们连一格都走不到。第一版没这条，「最适合网格的标的」前十全是货币基金。

### 9.3 形态量：波动率可预测，走势形态不可预测

特征期 2017-08~2021-12，检验期 2022-01~2026-08。同一只标的，两段之间：

| 形态量 | corr(特征期, 检验期) |
|---|---|
| 年化波动率 | **+0.680** |
| 滚动一年波动率中位数 | +0.613 |
| 效率比（净位移 ÷ 总路程） | **+0.315** |
| 滚动一年效率比中位数 | +0.277 |
| 一阶自相关 | +0.306 |

滚动窗口没有让效率比更稳（+0.277 < +0.315）—— 说明它**本来就不是**
一只标的的持久属性，换个窗口算也不是。

而决定网格成败的恰恰是效率比不是波动率：

| | → 网格绝对收益 | → 网格超额 |
|---|---|---|
| 检验期效率比（**事后**） | −0.156 | **−0.605** |
| 检验期波动率（事后） | −0.011 | −0.042 |
| 特征期效率比（**事前**） | −0.308 | −0.191 |
| 特征期波动率（事前） | −0.127 | +0.121 |

链条对得上：`0.315（持续性） × 0.605（同期效应） ≈ 0.19`，
实测事前效率比 → 超额 = **−0.191**。

**规律是真的，但「哪只标的将来会震荡」预测不了 —— 弱环在持续性上。**

### 9.4 板块分类：方向对，增量不显著

按名称分成 9 类（海外 / 商品 / 金融地产 / 消费医药 / 科技成长 / 周期资源 /
红利价值 / 宽基 / 其他）：

| 模型 | R² | 调整后 R² |
|---|---|---|
| 仅分类 | 0.304 | 0.211 |
| 仅「这只标的自己涨了多少」 | 0.387 | 0.378 |
| 分类 + 涨跌幅 | 0.518 | 0.445 |

分类在已知涨跌幅之上**多解释 13.1 个百分点**，`F = 2.00 (df 8, 59)`，
p ≈ 0.06 —— 不显著。而分类解释「涨跌幅」本身是 R² = 0.589。

也就是说：**分类之所以看起来管用，主要是因为同板块的标的一起涨跌，
而超额 ≈ −涨跌幅。分类本身没告诉你哪个板块会跌 —— 那是择时。**

### 9.5 按标的调参：走查下来是负收益

18 组参数（`levels{3,5,8}` × `step_pct{3,5,8}` × `stop_levels{0,4}`）
× 69 只，两段各跑一遍。

**跨标的不可迁移**：两两标的之间「18 组参数排名」的秩相关中位数
**+0.021**，只有 52% 为正 —— 抛硬币。

**跨时间也不可迁移**：同一只标的，特征期 vs 检验期的参数排名秩相关
**+0.049**，54% 为正。

检验期（2022~2026）超额中位数，三种选参方式：

| 选参方式 | 检验期超额中位数 |
|---|---|
| 按每只标的自己特征期最优 | +6.89% |
| 统一用特征期的全局最优 | +5.39% |
| **随便用一套（全部参数的中位数）** | **+8.61%** |
| 事后最优（上限，拿不到） | +17.21% |

**调参不如不调。** 两种拟合都跑输「什么都不挑」。
「按标的调参」比「统一一套」多赚 +0.00 pp，只在 39% 的标的上胜出。

那 `+17.21%` 的上限也是假的：每只标的内部 18 组参数的标准差是 8.52 pp，
而噪声基线只有 0.94 pp —— 参数确实造成了 9 倍于噪声的差异。
但在 18 个各自抖动 8.52 pp 的结果里纯挑最大值，
期望就会高出中位数 **15.48 pp**，而实测的「事后最优 − 中位数」只有 10.31 pp。
**选择偏差足以解释全部，还有富余。**

### 9.6 唯一稳的那个量

同一批 69 只标的、同一套参数、两个时期：

| | 买入持有中位数 | 网格中位数 | 网格超额 | 网格赢面 |
|---|---|---|---|---|
| 2017-08 ~ 2021-12 | **+44.0%** | +20.7% | −20.3% | 18/69 |
| 2022-01 ~ 2026-08 | **+12.9%** | +17.3% | +8.6% | 45/69 |

**网格自己的收益两段几乎一样（+20.7% / +17.3%，差 3.4 pp），
而买入持有从 +44.0% 掉到 +12.9%（差 31.1 pp）。**

所以「网格好不好」这个问题的答案，完全由后者决定 —— 而后者不可预测。
网格是**收益稳定器**，不是收益增强器。这是个正当的使用理由，
只是和「找一套最优参数」不是一回事。

（只有两个时期，n=2，这是提示不是定论。）

### 9.7 落到操作上

1. **一套参数用到底，不要按标的调。** 全局边际仍指向
   `step_pct 5~8`、`stop_levels 0`、`levels 5~8`，与第 8 节一致
2. **不要用历史形态挑网格标的。** 能拿到的预测力是 `r ≈ −0.19`，
   而且大半来自「过去涨多的将来跌」这种长周期反转，与网格无关
3. **要挑就挑波动率**（持续性 0.68）—— 但它决定的是**交易频次与摩擦**，
   不是盈亏（同期 corr 只有 −0.04）
4. 真正决定成败的是「这只标的接下来会不会涨」。那是择时问题，
   **不是网格参数问题** —— 这个海选到此为止能回答的就这么多
